# Assignment: Automated Ingestion: Building a Structured Knowledge Base (LLM Wiki + OKF) — Coding Problems

Put what you learned in **Automated Ingestion: Building a Structured Knowledge Base (LLM Wiki + OKF)** into code — but go beyond the lab. The lab turns a raw PDF into an `output_wiki/` folder of one-file-per-fact pages plus a master `index.md`, then answers a question in two phases by routing through the index first. The problems below extend that pipeline with the extraction prompt written from scratch, a parser for the OKF file layout, a filename-collision diagnosis, a deliberately truncated-JSON run that exercises the `JSONDecodeError` fallback, a second metadata field added to the OKF header and index line, a diagnosis of a code-fenced reply, an empty-selection branch that skips both LLM calls, and several checks that read the generated files back off disk instead of trusting memory.

**How to work:**

- Environment, API-key and LLM setup are not repeated here: reuse the setup from the first assignment (Classical RAG). Problems 4 onward assume you already have `llm` and `raw_text` (the text of the NASA Sun Fact Sheet PDF, extracted as in Step 1 of the lesson).
- Write each problem from scratch in a scratch Python file. Each problem says exactly what to print; print it.
- Problems 4 to 14 reuse `llm`, `raw_text`, `concepts`, `system_prompt`, `index_system_prompt`, `qa_system_prompt` and `user_query` from earlier problems (or from the lesson), so run them in one scratch file or notebook, in order. `system_prompt` comes from Problem 1; redefine the other two prompts and `user_query` from the lesson if you start fresh.
- Problems 1 to 3 need no LLM call. Problem 10 reuses only `strip_fences` from Problem 4 and makes no LLM call.
- Because LLM replies vary, your counts and filenames will differ from anyone else's; the printed format is what must match.

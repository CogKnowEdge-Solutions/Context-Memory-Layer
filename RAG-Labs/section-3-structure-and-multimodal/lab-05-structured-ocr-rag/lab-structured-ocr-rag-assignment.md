# Lab 5 Assignment: Structured OCR + RAG Chatbot: Chatting with Scanned Invoices — Coding Problems

Put what you learned in **Lab 5: Structured OCR + RAG Chatbot: Chatting with Scanned Invoices** into code — but go beyond the lab. The lab OCRs three scanned documents with `RapidOCR`, turns the raw text boxes into layout-preserving text via `result.to_markdown()`, embeds each whole document with a local `all-MiniLM-L6-v2` model, ranks documents with hand-rolled `cosine_similarity`, and answers through `rag_answer` with a `[Source: filename]` citation tag on every fact. The problems below reimplement that retrieval and citation machinery from scratch, swap the structured text back for the flat `result.txts` list to see what layout preservation is actually buying you, and sweep `top_k` so you can watch the explainability check in Step 8 start and stop marking documents as used. Write each problem from scratch in a scratch Python file. Each problem says exactly what to print; print it.

**1.** Write the API bootstrap: load the key with `load_dotenv(".env")` then `os.getenv("OPENROUTER_API_KEY")`, build `llm = ChatOpenAI(model="nvidia/nemotron-3-ultra-550b-a55b:free", api_key=OPENROUTER_API_KEY, base_url="https://openrouter.ai/api/v1", temperature=0, max_tokens=400)`, and set `CHAT_MODEL = "nvidia/nemotron-3-ultra-550b-a55b:free"` and `EMBED_MODEL = "all-MiniLM-L6-v2"`. Print `LLM ready.` followed by the value of `CHAT_MODEL` and the value of `EMBED_MODEL` on their own lines.

**2.** Write `download_invoices() -> dict` that recreates the `INVOICE_URLS` mapping with the keys `simple-invoice.png`, `contoso-receipt.png`, and `purchase-order-1.jpg`, creates the `invoices` directory with `os.makedirs("invoices", exist_ok=True)`, and for each entry calls `requests.get(url)`, calls `response.raise_for_status()`, and writes `response.content` to the joined path. Return the `{filename: path}` dictionary and print `Downloaded {filename} ({len(response.content)/1024:.1f} KB)` for each of the three documents.

**3.** Initialize `engine = RapidOCR(params={"Global.log_level": "error"})` once, loop over the downloaded paths, and call `engine(path)` for each, storing every result in an `ocr_results` dictionary keyed by filename. Print `{filename}: found {len(result.txts)} text boxes in {result.elapse:.2f}s` for all three documents, then print the total number of text boxes across every document.

**4.** Build `document_texts` by assigning `result.to_markdown()` for each entry in `ocr_results`. Print the character count of each document's structured text, then print the first 200 characters of `document_texts["simple-invoice.png"]`, then print one line reporting whether the substring `Invoice Number` appears in that document at all.

**5.** Compare the structured output against the flat one for `simple-invoice.png`: build `flat = " ".join(result.txts)` for that same OCR result and print `structured={len(structured)} chars | flat={len(flat)} chars`. Then test the **column** position of each label and value — write a helper that returns the character offset of a substring on the line that contains it — and print the offsets of `Invoice Number` and `34278587` in the structured text (they should land on the same column, `0` and `0`) alongside the offsets of the same two strings in the flat text. Finish by printing one line naming the property that separates the two versions. Watch out for the trap: a "are they on the same line?" test returns `False` for the structured text and `True` for the flat text, because flattening puts every token on one line by construction. That test measures the flattening, not the layout.

**6.** Write `embed_text(text: str) -> np.ndarray` that loads `embedder = SentenceTransformer("all-MiniLM-L6-v2")` once, calls `embedder.encode([text])`, and returns the first row of the result. Build a `knowledge_base` list where each entry is a dict with the keys `source`, `text`, and `embedding` for each filename in `document_texts`. Print `Knowledge base built with {len(knowledge_base)} documents.`, then for each entry print `{source} | {len(text)} chars | shape={embedding.shape} | first 3 values={rounded to 4 decimals}`. You should see a shape of `(384,)` for every document.

**7.** Write `cosine_similarity(a: np.ndarray, b: np.ndarray) -> float` yourself using `np.dot` and `np.linalg.norm`, then sanity-check it: pick one document's embedding from the `knowledge_base`, print `self-similarity: {cosine_similarity(v, v):.6f}`, and print the cosine similarity between the `simple-invoice.png` embedding and the `contoso-receipt.png` embedding. The self-similarity must come out at exactly `1.000000` — if it does not, your formula is wrong, not the model. The invoice-to-receipt similarity should land near `0.540`, which is the number to hold onto for problem 13: two documents from the same vendor still sit noticeably closer together than unrelated ones.

**8.** Write `retrieve(query: str, top_k: int = 2) -> list` that embeds the query, scores every `knowledge_base` entry with your `cosine_similarity`, sorts the scored dictionaries by the `score` key descending, and returns the first `top_k`. Call it on the query `"What is the total charge?"` three times with `top_k=1`, `top_k=2`, and `top_k=3`, and for each call print `top_k={k}` followed by `{doc['source']}  (similarity: {doc['score']:.3f})` for every returned document.

**9.** Write `rag_answer(query: str, top_k: int = 2) -> tuple` that calls your `retrieve`, joins the documents into a `labeled_context` where each block starts with `[Source: {doc['source']}]`, and posts a prompt that instructs the model to answer only from that context and tag every fact with its source. Set `query = "What is the invoice number and total charge on the Contoso invoice?"`, then print `--- DOCUMENTS RETRIEVED ---`, print `{doc['source']}  (similarity: {doc['score']:.3f})` for each retrieved document, print `--- ANSWER ---`, and print the returned answer.

**10.** Run the exact Step 8 explainability check over the documents returned in the previous problem: for each one, test `was_used = f"[Source: {doc['source']}]" in answer`, print `{doc['source']} | similarity: {doc['score']:.3f} | USED in answer` or `... | retrieved but NOT used` accordingly, and print a final line reading `Cited: {used_count} of {len(retrieved_docs)} documents`.

**11.** Extend the lab's prompt into a second function `rag_answer_strict(query: str, top_k: int = 2) -> tuple` that adds one instruction forbidding any sentence that lacks a `[Source: filename]` tag. Run the same `query` through `rag_answer` and through `rag_answer_strict`, print both answers in full, and print one line per answer reporting whether it contains at least one `[Source: ` substring.

**12.** Break the OCR step deliberately: build a second knowledge base in which `simple-invoice.png` is embedded from `" ".join(result.txts)` instead of `result.to_markdown()`, leaving the other two documents untouched. Re-run your `retrieve` and `rag_answer` from the earlier problems on the same `query` with `top_k=1`, print the retrieved filename, print the answer, and print one line diagnosing what the lost layout did to the numeric fields.

**13.** Inspect the knowledge base before asking any question: for each entry print `{source} | {len(text)} chars | dtype={doc['embedding'].dtype} | norm={np.linalg.norm(doc['embedding']):.4f}` — note that `all-MiniLM-L6-v2` returns unit-norm vectors, so every norm comes out `1.0000` and raw dot product would already be the cosine. Then print the full pairwise cosine similarity between the three document embeddings as three labelled lines. Expect roughly `0.540` for invoice-to-receipt, `0.301` for invoice-to-purchase-order, and `0.401` for receipt-to-purchase-order — so you can see how far apart the invoice, the receipt, and the purchase order sit in the embedding space, and why the invoice and receipt are hard to tell apart from each other but both stand well clear of the purchase order.

**14.** Write `chatbot(questions: list) -> None` that loops over the supplied questions instead of calling `input()`, calls `rag_answer` for each, and prints `[Retrieved: {comma-separated sources}]` followed by the answer. Run it with the three questions `"What is the invoice number?"`, `"What is the purchase order number?"`, and `"What is the bank account number for this vendor?"`, then print `Goodbye!` after the loop finishes — the third question is the one that should trigger the prompt's `Not found in the provided documents.` fallback, so print one line stating whether it did.

# Assignment: End-to-End Graph RAG — From NetworkX to Neo4j — Coding Problems

Put what you learned in **End-to-End Graph RAG — From NetworkX to Neo4j** into code, but go beyond the lab. The lab asked `nvidia/nemotron-3-super-120b-a12b:free` (through OpenRouter) once for `source`/`relation`/`target` triples, built an in-memory NetworkX graph and walked it up to 2 hops, then wrote the same triples into Neo4j Aura with `MERGE`, read them back with Cypher, and answered the same question both ways with a `--- FINAL ANSWER ---` block followed by a `--- AI TRACING & EXPLAINABILITY ---` block. The problems below rebuild that chain from scratch in two parts: problems 1-9 cover three offline toy graphs, the triples from the PDF, the NetworkX graph, and the in-memory answer; problems 10-14 cover Neo4j, Cypher, and the answer from the database (Neo4j starts at problem 10). Along the way you see what stripping does to node counts, watch a second relation overwrite the first, cap the number of triples, break the JSON parser on purpose, compare 1-hop and 2-hop walks, prove `MERGE` never duplicates a node, and test what changes when a Cypher walk follows arrows forward only.

Write each problem from scratch in a scratch Python file. Each problem says exactly what to print; print it. Problems 1-9 are in-memory NetworkX; Neo4j starts at problem 10. Environment, API-key and LLM setup are not repeated here: reuse the setup from the first assignment (Classical RAG).

**State carries over between problems.** Run them in order in one session. `triples` (problem 4) feeds problems 6 and 11; the graph `G` (problem 6) is used by problems 7, 8, 9, 12, and 14; the database loaded in problem 11 is needed by problems 12-14. Problems 11-14 need your Neo4j Aura credentials, and problem 11 **wipes the whole database**, so use a throwaway instance (the later vector + graph hybrid lesson also uses the `:Concept` label, so do not leave this data in a database you plan to reuse there).

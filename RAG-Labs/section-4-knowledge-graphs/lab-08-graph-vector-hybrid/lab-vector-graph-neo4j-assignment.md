# Assignment: Hybrid RAG: Vector Search + Graph Traversal — Coding Problems

Put what you learned in **Hybrid RAG: Vector Search + Graph Traversal** into code — but go beyond the lab. The lab extracts entities and relationships from the Attention Is All You Need PDF into `:Concept` nodes, stores a 384-dimension `all-MiniLM-L6-v2` vector on each node, indexes them as `concept_embeddings`, and answers a question with one Cypher call that combines `db.index.vector.queryNodes` seed selection with `(seed)-[r]-(neighbor:Concept)` expansion. The problems below check the 384-dimension assumption before it reaches the index, pre-flight the database, add hand-built orphan relationship entries, read the node, relationship, and vector counts back out of Neo4j instead of assuming them, break the vector index with a mismatched `vector.dimensions`, sweep `top_k`, exercise the empty-facts guard, and compare what vector search alone returns with what the hybrid query returns.

**How to work**

- Write each problem **from scratch** in a scratch Python file.
- Each problem names **exactly what to print**. Print it, with that exact wording.
- Environment, API-key and LLM setup are not repeated here: reuse the setup from the first assignment (Classical RAG); the Neo4j connection is the one you built in the graph RAG assignment.
- Read the connection settings from `.env` (`NEO4J_URI`, `NEO4J_USERNAME`, `NEO4J_PASSWORD`, `OPENROUTER_API_KEY`); never paste secrets into code.
- When a problem asks for a prediction, write it as a comment before you run the code, then explain any gap.
- Run the problems in order; they share one Neo4j database.

**State dependencies:** the problems share one Neo4j database, so run them in order. `embeddings` comes from Problem 1, `driver` from Problem 2 (the graph RAG connection), and `llm` from the first assignment. Problems 5 and 6 need the extraction from Problem 4; Problem 9 needs the nodes from Problem 5, the index from Problem 8 and `embeddings`; Problems 11 to 14 need the nodes, relationships, the 384-dimension index and the vectors from Problems 5 to 9. Problem 10 changes the index, so finish it by recreating the 384 index; Problem 14 also needs the `execute_hybrid_retrieval` function from Problem 11. Writing the relationships twice duplicates them (see Problem 6), so if you need a clean start run `MATCH (n:Concept) DETACH DELETE n` (it deletes each node together with all its relationships) and rebuild from Problem 5.

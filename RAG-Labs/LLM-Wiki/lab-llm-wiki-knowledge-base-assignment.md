# Lab 6 Assignment: Automated Ingestion: Building a Structured Knowledge Base (LLM Wiki + OKF) — Coding Problems

Put what you learned in **Lab 6: Automated Ingestion: Building a Structured Knowledge Base (LLM Wiki + OKF)** into code — but go beyond the lab. The lab turns a raw PDF into an `output_wiki/` folder of one-file-per-fact pages plus a master `index.md`, then answers a question in two phases by routing through the index first. The problems below extend that pipeline with a parameterized `ChatBedrockConverse` factory, a deliberately truncated-JSON run that exercises the `JSONDecodeError` fallback, a second metadata field added to the OKF header and index line, an empty-selection branch that skips both LLM calls, and several checks that read the generated files back off disk instead of trusting memory. Write each problem from scratch in a scratch Python file. Each problem says exactly what to print; print it.

**1.** Write the environment bootstrap: call `load_dotenv()`, then assert that `os.environ["AWS_ACCESS_KEY_ID"]`, `os.environ["AWS_SECRET_ACCESS_KEY"]`, `os.environ["AWS_ENDPOINT_URL"]`, and `os.environ["AWS_REGION"]` are all non-empty, and print `AWS Bedrock credentials configured.` followed by `✓ All environment variables loaded successfully`.

**2.** Write an `init_llm(temperature: float = 0.0) -> ChatBedrockConverse` function that returns `ChatBedrockConverse(model="global.amazon.nova-2-lite-v1:0", temperature=temperature, max_tokens=8000)`. Call it twice — once with no argument and once with `0.7` — then print the `.temperature` attribute of each returned client as `Extraction temperature: 0.0` and `Creative temperature: 0.7`.

**3.** Build the download-and-extract step from scratch: set `pdf_url` to the NASA Sun Fact Sheet link ending in `SunFactSheet.pdf`, `GET` it with `requests.get`, write the bytes to `data/SunFactSheet.pdf`, then open it with `PyPDF2.PdfReader` and loop over `reader.pages` appending `page.extract_text() + "\n"` into `raw_text`. Print the page count as `Pages in PDF: N` and then `Extracted {len(raw_text)} characters.`.

**4.** Write a `strip_fences(raw: str) -> str` helper that strips whitespace, then — only if the text starts with a markdown code fence — splits on that fence marker, takes index `1`, drops a leading `json` language tag if present, and strips again. Use it on `llm.invoke(f"{system_prompt}\n\nDocument Text:\n{raw_text}")`, `json.loads` the result, and assign `concepts = structured_data.get("concepts", [])`. Print `Success! AI identified {len(concepts)} distinct concepts.` and then print the `title` of the first three concepts, one per line, prefixed with ` - `.

**5.** Break the extraction step deliberately: `json.dumps(concepts)`, slice off the last 40 characters to simulate a reply that got cut off mid-object, and feed that truncated string through `json.loads` inside a `try` / `except json.JSONDecodeError` block that sets `concepts = []`. Print `Caught: {type(e).__name__}`, then the lab's two lines `Error: The model's JSON response was cut off or malformed.` and `Try reducing the amount of source text, or check the raw output below:`, then the final 500 characters of the truncated string as `Tail: {truncated[-500:]}`.

**6.** Rebuild the writer from scratch: set `output_dir = "output_wiki"`, call `os.makedirs(output_dir, exist_ok=True)`, set `index_path = os.path.join(output_dir, "index.md")`, and seed it with `"# Master Index\n\n"` only if `os.path.exists(index_path)` is `False`. Then loop over `concepts`, clean each name with `concept['filename'].replace(" ", "_").lower()` plus an `if not filename.endswith('.md')` fix, write a file whose body is the OKF block `type: / title: / tags: / description:` followed by `---`, `# {title}`, and `{content}`, print `Created: {filename}`, and append `- **{filename}**: {concept['description']}` to the index with mode `"a"`. Print `Output directory ready at: output_wiki` first and `Total files written: {len(concepts)}` last.

**7.** Read the result back off disk instead of trusting memory: list `os.listdir("output_wiki")`, count entries ending in `.md` that are not `index.md` to get the file count, count the non-empty lines of `index.md` starting with `- **` to get the index-line count, and check that every filename mentioned in the index actually exists in the directory. Print `Concept files: {file_count}`, `Index lines: {index_line_count}`, then one explanatory line of the form `The index holds {index_line_count} lines of description for {file_count} files and zero facts.`, then print `✓ Every index entry resolves to a file` or, if any name is missing, print `Missing from disk: {missing}` for each one.

**8.** Extend the writer with an extra metadata field: add a `source: SunFactSheet.pdf` line to the OKF header for every file, and change the index line format to `- **{filename}** [{concept['tags']}]: {concept['description']}` so each entry carries its tags. Point the writer at a fresh directory `output_wiki_tagged`, run it over the same `concepts`, then print the first eight lines of `output_wiki_tagged/{first_filename}` with a `1: ` style line-number prefix, and print `Index entries carrying tags: {tagged_line_count}`.

**9.** Rebuild Phase 1 exactly as the lab does: read `index_content` from `output_wiki_tagged/index.md`, build `prompt_1` from `index_system_prompt` plus the table of contents plus `user_query`, call `llm.invoke(prompt_1)`, run the reply through `strip_fences` and `json.loads`, and set `selected_files = retrieval_data.get("files_to_read", [])`. Print `Success! The LLM requested {len(selected_files)} file(s):` and then each filename on its own line prefixed with ` - `.

**10.** Break Phase 1 on purpose: rebuild `prompt_1` but substitute the full concatenated text of every concept file for the `Table of Contents:` section, run it through `llm.invoke`, and print how many filenames it returns compared with the count from the index-based run, using the format `Index-only run returned {index_count} file(s) vs {full_text_count} file(s) when given every file.`. Finish with one printed line explaining in one sentence why the index-first design is what keeps the answer grounded, naming the phrase `files actually relevant`.

**11.** Rebuild Phase 2: loop over `selected_files`, and for each existing path append `"--- START OF {filename} ---\n{contents}\n--- END OF {filename} ---\n\n"` into `loaded_context`, printing `Warning: {filename} not found on disk.` for any missing file. Then invoke `llm.invoke(prompt_2)` with `qa_system_prompt`, `loaded_context`, and `user_query`, `json.loads` the reply into `final_result`, and print the three sections exactly as the lab does — `EXPLAINABILITY TRACE`, one `-> {step}` per entry of `trace_path`, then `SOURCES CITED` with one `- {source}` per entry of `sources_used`, then `FINAL ANSWER` and the `answer` value.

**12.** Add a branch the lab leaves implicit: wrap the whole two-phase run in an `answer_question(user_query: str) -> str` function that returns the literal string `No relevant files selected.` immediately when `selected_files` is empty, skipping both LLM calls. Call it with the off-topic question `"What is the boiling point of water at sea level?"`, and print `Branch taken: no-files-selected` when the guard fires or `Branch taken: full two-phase run` when it does not, followed by the returned string.

**13.** Cross-check the answer against the files instead of trusting it: compare the `sources_used` list from `final_result` against `selected_files`, and for each cited source confirm it both appeared in `selected_files` and exists on disk in `output_wiki_tagged`. Print `Verified sources: {verified} of {len(sources_used)}`, then print `⚠ Cited but never selected: {orphan}` for each source that fails either check, or print `✓ Every cited source is on disk and was selected by Phase 1` when nothing fails.

**14.** Run the full pipeline end to end into a brand-new directory `output_wiki_v2`, then ask three different questions through your `answer_question` function: `"What is the mass of the Sun?"`, `"How does solar activity vary over the 11-year cycle?"`, and `"What is the composition of the Sun's photosphere?"`. For each one print a single line in the form `Q: {question}` and `A: {answer}` using only the first 160 characters of the answer, and close with one printed line stating `Knowledge base rebuilt once, queried {question_count} times.` so the cost argument is visible in the output.

# Lab 1 Assignment: Classical RAG: The Canonical Pipeline — Coding Problems

Put what you learned in **Lab 1: Classical RAG: The Canonical Pipeline** into code — but go beyond the lab. The lab loads a two-page PDF with PyMuPDF, slices it into 500-character chunks with 50 characters of overlap, embeds each chunk with `all-MiniLM-L6-v2`, stores the normalized vectors in a FAISS `IndexFlatIP`, retrieves the top-3 by cosine similarity, and asks an OpenRouter model to answer from those chunks alone. The problems below pull every stage apart so you can measure it on its own — count chunks, verify the normalization that makes inner product equal cosine, compare an inner-product index against an L2 one, and then break the retriever on purpose to find out what the settings you copied were quietly protecting you from. Write each problem from scratch in a scratch Python file. Each problem says exactly what to print; print it.

**1.** Write the environment bootstrap: call `load_dotenv(".env")`, read `OPENROUTER_API_KEY` with `os.getenv` and fall back to `input(...)` when it comes back `None`, build an `OpenAI(base_url="https://openrouter.ai/api/v1", api_key=OPENROUTER_API_KEY)` client, and load `SentenceTransformer("all-MiniLM-L6-v2")`. Print `Key loaded.`, then `Embedding model ready: {n} dimensions` using `embedder.get_sentence_embedding_dimension()`, then the `.model_name_or_path` of the embedder you just built.

**2.** Load `data/sample_text_document.pdf` with `pymupdf.open(...)` and concatenate every page's `get_text()` into one string with `"\n".join(...)`. Print `Loaded {n} page(s), {c} characters.` for the page count and total length, then loop over the pages a second time and print one line per page in the form `page {i+1}: {first 60 characters of that page's text}` so you can see where the page boundary falls in the combined string.

**3.** Write `chunk_text(text, size, overlap) -> list` exactly as the lab does — a `while` loop that slices `text[start:start + size]`, strips it, and advances `start` by `size - overlap`, filtering out empty chunks. Call it three times on the same text with `(500, 50)`, `(500, 0)`, and `(200, 50)`, and print one line per call in the form `size={size}, overlap={overlap} -> {count} chunks, mean {m:.0f} chars` where `m` is the mean `len(chunk)`, so the overlap and size both visibly change the count.

**4.** Embed the `(500, 50)` chunks twice — once with `normalize_embeddings=True` and once with `normalize_embeddings=False` — casting each to `float32`. Print `shape={embeddings.shape}` for each, then print `normalized norm={np.linalg.norm(a):.4f} | raw norm={np.linalg.norm(b):.4f}` for `a = embeddings[0]` and `b = raw[0]`, so you can see the first is length 1 and the second is not.

**5.** Build `index = faiss.IndexFlatIP(embeddings.shape[1])`, add the normalized embeddings, then print `index.ntotal` and `index.d`. Embed the default lab question `"Why do restoration teams reintroduce tidal flow gradually instead of all at once?"` and call `index.search(query_vector, 3)` directly. Print the raw `scores[0]` array and the raw `indices[0]` array on their own lines, so you see exactly what FAISS hands back before any list comprehension turns it into tuples.

**6.** Build a second index `l2 = faiss.IndexFlatL2(embeddings.shape[1])` and add the same normalized embeddings to it. Search both indexes with the same question and `k=1`, and print `inner-product: index={i_ip} score={s_ip:.4f}` then `l2-distance: index={i_l2} distance={d_l2:.4f}`. Print one final line stating whether the two indexes returned the same chunk index, and explain in that same line why an L2 index was unnecessary given the vectors were already normalized.

**7.** Write `retrieve(question, top_k=3) -> list` that embeds the question with `normalize_embeddings=True`, calls `index.search`, and returns a list of `(int(index), float(score))` tuples. Call it with the default question at `top_k=1`, `top_k=3`, and `top_k=5`, and for each run print `top_k={k}:` followed by one line per hit in the form `  chunk {rank}: idx={i} cosine={score:.3f} | {first 80 characters of chunks[i]}`.

**8.** Judge the retriever instead of trusting it. For the `top_k=3` hits from the previous problem, print one line per chunk in the form `chunk {i}: mentions 'gradually'={True or False}, mentions 'phased'={True or False}` by testing the lowercase chunk text. Then print a single line `on-topic hits: {n}/3` counting how many of the three retrieved chunks are actually about phasing, and explain in that line why the retriever still returned three chunks regardless of how many were on-topic.

**9.** Write `build_context(question, top_k=3) -> tuple` that calls `retrieve`, joins the hit chunks into a string with `"[{n}] {chunk}"` labels separated by blank lines, and returns the context string plus the hits. If the answer is not in the context, say you don't know.\n\nContext:\n{context}\n\nQuestion: {question}\nAnswer:"` — under a `PROMPT:` header so you can read the exact instruction the model receives.

**10.** Send the prompt from the previous problem to the model with `client.chat.completions.create(model=MODEL, messages=[{"role": "user", "content": prompt}], temperature=0, max_tokens=512)`, print the answer under an `Answer:` line, and print the first hit's cosine score on its own line. Then ask the completely off-topic question `"Who won the 1998 FIFA World Cup?"` through the same pipeline, print its answer, and print one line comparing the top-1 cosine score of the on-topic question against the off-topic one.

**11.** Measure how chunk size changes retrieval.

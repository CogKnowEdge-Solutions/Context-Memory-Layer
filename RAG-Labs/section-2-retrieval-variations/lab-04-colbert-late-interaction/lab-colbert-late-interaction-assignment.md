# Assignment: ColBERT & Late Interaction RAG — Coding Problems

Put what you learned in **ColBERT & Late Interaction RAG** into code — but go beyond the lab. The lab embeds every token of every chunk with `colbert-ir/colbertv2.0`, stores the resulting `(num_tokens, 128)` matrices in a Qdrant `MAX_SIM` multivector collection, and answers a BERT-paper question through a late-interaction search plus an LCEL chain. The problems below measure the token matrices themselves, add a hand-written MaxSim implementation so you can see the three scoring steps yourself, run a predict-then-verify check on document versus query embeddings, read the collection config and point count back out of Qdrant, sweep `top_k`, break the pipeline twice, and finally check Qdrant's ranking against your own MaxSim and against a single mean-pooled vector.

**How to work.** Write each problem from scratch in a scratch Python file. Each problem says exactly what to print; print it. Problems build on each other: keep one scratch file and run top to bottom. Environment, API-key and LLM setup are not repeated here: reuse the setup from the first assignment (Classical RAG). The PDF download and the 500-character chunking are not repeated either: reuse `chunks_500` (used as `chunks`) from the lab's `bert_paper.pdf` ingestion. Problem 1 builds `colbert`, which problems 3 to 7, 10, 11 and 14 reuse. Problems 3, 4, 5, 6, 8 and 10 reuse `chunks_500`, and problems 10 and 14 reuse `stable_id` from 8. Problem 9 defines `client` and `COLLECTION_NAME`, and problems 10 to 14 need them and the Qdrant collection from 9. Problem 14 also reuses `maxsim` (5), `chunk_embeddings` (10) and `retrieve` (11).

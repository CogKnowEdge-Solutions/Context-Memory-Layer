# Lab 8 Assignment: End-to-End Graph RAG with Neo4j — Coding Problems

Put what you learned in **Lab 8: End-to-End Graph RAG with Neo4j** into code — but go beyond the lab. The lab built an end-to-end graph RAG pipeline that pulls a PDF's text with `PyPDF2`, asks `nvidia/nemotron-3-ultra-550b-a55b:free` for `source`/`relation`/`target` triples, `MERGE`s them into Neo4j Aura with a parameterized Cypher query, and answers a question with a `--- FINAL ANSWER ---` block followed by a `--- AI TRACING & EXPLAINABILITY ---` block. The problems below rebuild that whole chain from scratch, tighten the extraction prompt and cap the triple count, replay the ingestion twice to prove `MERGE` never duplicates a node, read node and relationship counts back out of Neo4j with your own Cypher, add a `hops` parameter so traversal can go past a node's direct neighbors, deliberately break `find_node_in_db` and the OpenRouter payload to see the failure messages, and reopen the database through a second connection to prove the graph outlives the process. Write each problem from scratch in a scratch Python file. Each problem says exactly what to print; print it.

**1.** Write the environment bootstrap: load `.env` with `python-dotenv`, then assert that `OPENROUTER_API_KEY`, `NEO4J_URI`, `NEO4J_USER`, and `NEO4J_PASSWORD` are all non-empty, and print `✓ All environment variables loaded successfully`.

**2.** Write the download step from scratch: `requests.get` the URL `https://arxiv.org/pdf/1706.03762.pdf`, `os.makedirs("data", exist_ok=True)`, and write the bytes to `data/document.pdf`. Print the number of bytes written and the exact line `Success! Saved PDF to: data/document.pdf`.

**3.** Write `extract_first_page_text(pdf_path: str, char_limit: int = 1500) -> str` using `PyPDF2.PdfReader` and `reader.pages[0].extract_text()`, trimming with `[:char_limit].strip()`. Call it on `data/document.pdf` and print `Success! Extracted {len(text)} characters ready for processing.` followed by the first 80 characters of the text on their own line.

**4.** Write `extract_graph_elements(text, max_triples=12) -> list[dict]` from scratch: build a prompt that asks `nvidia/nemotron-3-ultra-550b-a55b:free` for a pure JSON list of objects with keys `source`, `relation`, and `target`, tell it to return at most `max_triples` entries, and post it to `https://openrouter.ai/api/v1/chat/completions` with `temperature=0.0`. Strip any markdown fence the same way the lab does before calling `json.loads`. Call it on the text from problem 3 and print the number of triples returned plus the first triple as `json.dumps(triples[0], indent=2)`.

**5.** Deliberately break the parsing on purpose: write `parse_raw_json(raw: str) -> list` that calls `json.loads(raw)` with no fence-stripping, then feed it a fake LLM reply that wraps the JSON in a fenced `json` block. Print `Extraction Error: JSONDecodeError` and confirm by printing that the function returned `[]`.

**6.** Write `normalize_relation(relation: str) -> str` from scratch that reproduces the lab's transformation — strip, then replace spaces and hyphens with underscores, then uppercase — using a single `re.sub` call. Apply it to `"has author"`, `"is-a-type-of"`, and `"part of"`, and print the three resulting Neo4j relationship types on separate lines.

**7.** Write `write_triples(tx, triples) -> int` from scratch: for each `(source, relation, target)` tuple it runs exactly one parameterized Cypher query containing `MERGE (s:Concept {name: $source})`, `MERGE (t:Concept {name: $target})`, and `MERGE (s)-[:{relation_type}]->(t)`, counting the `tx.run` calls it issued and returning that count. Pass it three hand-written triples — `("Transformer", "relies on", "Attention Mechanism")`, `("Transformer", "has-part", "Encoder")`, and `("Encoder", "uses", "Feed-Forward Network")` — and print the number of queries run.

**8.** Prove `MERGE` is idempotent: open a session with `GraphDatabase.driver(NEO4J_URI, auth=(NEO4J_USER, NEO4J_PASSWORD))`, run `session.run("MATCH (n) DETACH DELETE n")`, then call `session.execute_write(write_triples, triples)` twice in a row with the same three triples from problem 7. Afterward run `MATCH (n:Concept) RETURN count(n) AS c` and `MATCH ()-[r]->() RETURN count(r) AS c`, and print both counts followed by the line `Safe to re-ingest: True`.

**9.** Inspect the stored graph back with your own Cypher instead of trusting memory: run `MATCH (n:Concept) RETURN n.name AS name ORDER BY name LIMIT 10` and print the ten names, then run `MATCH ()-[r]->() RETURN type(r) AS rel, count(*) AS c ORDER BY c DESC LIMIT 3` and print the three most common relationship types with their counts. Finally open a second, independent driver connection to the same instance, count `Concept` nodes through it, and print `Persistence check: {count}` to show the graph survived outside the original session.

**10.** Write `find_node_in_db(question: str) -> str | None` from scratch using the exact Cypher the lab uses, `MATCH (c:Concept) RETURN c.name AS name`, and returning the first node name whose lowercased form appears in the lowercased question. Run it against `"What mechanism does the Transformer architecture rely on?"` and `"What does the Encoder use?"`, and print each question followed by `Detected concept: {name}`.

**11.** Extend that same function with the no-match branch: call it with `"What is the price of coffee in Zurich?"`, print exactly `Could not find any known concepts from the database in your question.`, and then print one additional line explaining in a single sentence why a substring match will fail whenever the question uses a synonym instead of the literal node name.

**12.** Write `fetch_graph_context(entity_name: str, hops: int = 1) -> list[str]` from scratch with two branches: when `hops == 1` run the lab's undirected single-hop pattern `MATCH (n:Concept {name: $name})-[r]-(m:Concept) RETURN n.name AS source, type(r) AS relation, m.name AS target` and format each row as `{source} --[{relation}]--> {target}`; when `hops == 2` run a variable-length path `MATCH p=(n:Concept {name: $name})-[*1..2]-(m:Concept) RETURN n.name AS source, [x IN nodes(p) | x.name] AS path` and format each row as `{source} => {" -> ".join(path)}`. Call it for `"Transformer"` at `hops=1` and at `hops=2` and print both fact counts, then print the count of facts unique to the `hops=2` call.

**13.** Write `execute_neo4j_rag(question: str) -> str` from scratch: call `find_node_in_db`, print `[System Log] Auto-detected focus concept: '{target_entity}'`, call `fetch_graph_context` with `hops=2`, build `facts_block` as a bullet list with `- ` prefixes, and post a prompt demanding exactly two sections — `--- FINAL ANSWER ---` and `--- AI TRACING & EXPLAINABILITY ---` — to `nvidia/nemotron-3-ultra-550b-a55b:free` at `temperature=0.0`. Call it with `"What mechanism does the Transformer architecture rely on?"`, then print two booleans on separate lines: whether the returned text contains `--- FINAL ANSWER ---`, and whether it contains `--- AI TRACING & EXPLAINABILITY ---`.

**14.** Deliberately break the model call: reuse the same payload and headers from problem 13 but set `"model"` to the nonexistent id `"nvidia/not-a-real-model:free"`, keep `resp.raise_for_status()`, and wrap the post in `try`/`except`. Catch the exception and print the HTTP status code from `resp.status_code` on one line and the `error.message` field of `resp.json()` on the next, so you can see exactly what a rejected OpenRouter request returns.

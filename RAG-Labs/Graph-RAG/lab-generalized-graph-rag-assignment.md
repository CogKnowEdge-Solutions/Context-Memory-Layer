# Lab 7 Assignment: End-to-End Generalized Graph RAG — Coding Problems

Put what you learned in **Lab 7: End-to-End Generalized Graph RAG** into code — but go beyond the lab. The lab pulls the first 1500 characters out of the Attention Is All You Need PDF, asks `openai/gpt-oss-20b:free` for `source`/`relation`/`target` triples, folds them one at a time into an `nx.DiGraph`, then answers a question by matching an entity with `find_node_in_question`, walking outward with `traverse_subgraph(radius=2)`, and formatting the LLM's reply into `--- FINAL ANSWER ---` and `--- AI TRACING & EXPLAINABILITY ---` sections. The problems below rebuild the extraction, the graph walk, and the query engine from scratch, add the direction and radius parameters the lab leaves implicit, and then break the JSON contract and the entity matcher on purpose to find out which parts of that pipeline are load-bearing. Write each problem from scratch in a scratch Python file. Each problem says exactly what to print; print it.

**1.** Write the key bootstrap the lab's config cell uses: read `OPENROUTER_API_KEY` with `os.getenv`, fall back to `input("Enter your OpenRouter API key: ").strip()` when it is missing, and set `OPENROUTER_URL = "https://openrouter.ai/api/v1/chat/completions"` and `TEXT_MODEL = "openai/gpt-oss-20b:free"`. Print `Success: API Key loaded!` when the key came from the environment and `Key entered manually.` when it came from the prompt, then print `OPENROUTER_URL` and `TEXT_MODEL` on their own lines.

**2.** Download `https://arxiv.org/pdf/1706.03762.pdf` into `data/document.pdf` yourself: `os.makedirs("data", exist_ok=True)`, `requests.get(PDF_URL)`, `response.raise_for_status()`, then write `response.content` to the joined path. Print `Downloading document...`, print `Success! PDF stored at: {PDF_PATH}`, and print the file size in KB.

**3.** Extract the text with `PyPDF2.PdfReader`, take `reader.pages[0]`, call `extract_text()`, and slice the result to `sample_text[:1500].strip()`. Print `Success! Extracted {len(sample_text)} characters.`, then print the last 60 characters of `sample_text` so the hard cut point is visible, then print one line saying whether the truncated text ends on a sentence boundary.

**4.** Write `extract_graph_elements(text: str) -> list` from scratch: build the prompt that demands a bare JSON list of objects keyed `source`, `relation`, and `target` with no Markdown fences and no commentary, post it to `OPENROUTER_URL` with `model=TEXT_MODEL`, `temperature=0.0`, and an `Authorization: Bearer` header, then `json.loads` the `choices[0].message.content` and return it. Call it on `sample_text`, print `Extracted {len(extracted_relationships)} relationships:`, and print `json.dumps(extracted_relationships, indent=2)`.

**5.** Harden the reply parser: write `strip_code_fences(raw: str) -> str` that drops a leading triple-backtick fence line and a trailing triple-backtick line when the reply is wrapped in a fence, and use it inside your `extract_graph_elements`. Feed the helper three deliberately messy raw replies — a bare JSON array, a fenced `json` array, and a fenced array preceded by the sentence `Here are the relationships I found:` — and for each print the first 30 characters of the cleaned string plus `{len(json.loads(cleaned))} triples parsed` or `parse failed`.

**6.** Build the graph with `G = nx.DiGraph()`, loop over the extracted triples, and call `G.add_edge(src, tgt, relation=relation_type)` after stripping whitespace from `rel["source"]`, `rel["relation"]`, and `rel["target"]`. Print `Graph constructed successfully!`, print `Total Nodes: {G.number_of_nodes()}`, and print `Total Edges: {G.number_of_edges()}`.

**7.** Inspect the finished graph rather than trusting it: for every node in `G.nodes()` print `{node} | in={G.in_degree(node)} | out={G.out_degree(node)}`, then print the node with the highest out-degree and the node with the highest in-degree, each on its own line, and print one line reporting whether any node has both degrees equal to zero.

**8.** Write `find_node_in_question(question: str, graph) -> str` yourself, looping over `graph.nodes()` and returning the first node whose lowercased name appears in the lowercased question. Run it on the lab's `query_1 = "What mechanism does the Transformer architecture rely on?"`, on the paraphrase `"What does the Transformer depend on to weigh tokens?"`, and on `"What is the capital of France?"`. Print the matched node or `None` for each of the three, plus one line explaining what the second question demonstrates about the matcher's behaviour.

**9.** Write `traverse_subgraph(graph, start_entity: str, radius: int = 2) -> list` from scratch: resolve the target with a case-insensitive substring match over `graph.nodes`, BFS out with `nx.single_source_shortest_path_length(graph, target_node, cutoff=radius)`, take the `.keys()` as `sub_nodes`, build `graph.subgraph(sub_nodes)`, and format each edge as `f"{u} --[{data.get('relation', 'CONNECTED_TO')}]--> {v}"`. Call it for `"Transformer"` with `radius=1` and again with `radius=2`, print `radius=1 -> {n} facts` and `radius=2 -> {n} facts`, and print every fact string that appears only in the `radius=2` result.

**10.** Extend the traversal with a new parameter: add a `direction: str = "out"` argument to your function that accepts `"out"`, `"in"`, and `"both"`, selecting neighbours via `graph.successors(n)` or `graph.predecessors(n)` or the union of the two. Call it on `"Attention Mechanism"` once per direction with `radius=1`, print `{direction} -> {n} facts` for each, and print the fact strings that the `"both"` run found that the `"out"` run did not.

**11.** Write `execute_graph_rag(question: str, radius: int = 2) -> str` from scratch, wiring your own `find_node_in_question` and `traverse_subgraph` into it: return the early-exit message listing known concepts when no entity matches, print `[System Log] Auto-detected focus concept: '{target_entity}'` when one does, build `facts_block` by prefixing every fact with `- `, and post the prompt that demands exactly the `--- FINAL ANSWER ---` and `--- AI TRACING & EXPLAINABILITY ---` sections in third person. **12.** Break the matcher on purpose: call your `execute_graph_rag` with `"How does photosynthesis work?"`, which names no entity in the graph. Print the exact early-return string you get, including the first five entries of `list(G.nodes)`, then print one line explaining why the pipeline refuses to call the LLM at all instead of handing it an empty fact list.

**13.** Sweep the radius through the full engine: call `execute_graph_rag` twice on the same `query_1`, once with `radius=1` and once with `radius=2`. **14.** Print a single line, and nothing else, that explains why `find_node_in_question` uses a case-insensitive substring match against node names instead of an embedding similarity search — and say what that choice implies about how the question has to be worded for the graph to be hit at all.

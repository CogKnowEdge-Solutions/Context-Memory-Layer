# Lab 3 Assignment: Parent-Child & Summary-Based Multi-Vector RAG — Coding Problems

Put what you learned in **Lab 3: Parent-Child & Summary-Based Multi-Vector RAG** into code — but go beyond the lab. The lab splits the Attention Is All You Need PDF into ~10,000-character `parent_docs`, cuts those into ~400-character `child_docs`, condenses each parent into an LLM `summary_doc`, stamps every child and summary with the parent's SHA-256 `doc_id`, and lets `MultiVectorRetriever` swap whichever small piece wins the search for its full parent before the LLM answers. The problems below rebuild each of those layers separately, prove programmatically that the text that wins the search is never the text the LLM reads, sweep the two chunk sizes and `search_kwargs={"k": ...}` to see the context grow, and then break the two links that make the swap possible to find out what they were silently doing. Write each problem from scratch in a scratch Python file. Each problem says exactly what to print; print it.

**1.** Configure both models exactly as the lab does: `ChatOpenAI(openai_api_key=..., openai_api_base="https://openrouter.ai/api/v1", model_name="openai/gpt-oss-20b:free", temperature=0.0)` and `HuggingFaceEmbeddings(model_name="all-MiniLM-L6-v2")`. Print the `model_name` in use, the `openai_api_base` in use, and the dimension of a test embedding produced by `embeddings.embed_query("a short probe sentence")`, one per line.

**2.** Download `https://arxiv.org/pdf/1706.03762.pdf` into a local file with `requests.get` plus `response.raise_for_status()`, then extract every page with `PdfReader` and join the page texts with newlines into `raw_text`. Print `Extracted {len(raw_text)} characters.`, then print the number of pages the reader reported and the first 100 characters of `raw_text`.

**3.** Write `make_parents(raw_text: str, chunk_size: int = 10000, chunk_overlap: int = 200) -> list` that runs `RecursiveCharacterTextSplitter(chunk_size=chunk_size, chunk_overlap=chunk_overlap).split_text(raw_text)` and wraps each chunk in a `Document(page_content=chunk)`. Print `Created {len(parent_docs)} Parent Documents.`, then for each parent print `{i} | {len(doc.page_content)} chars | {first 60 characters}`.

**4.** Write `stable_id(text: str) -> str` yourself, hashing the UTF-8 bytes with `hashlib.sha256` and returning the hex digest. Print the full `doc_id` of `parent_docs[0]`, print the same value truncated to its first 16 characters, and print `stable: {stable_id(t) == stable_id(t)}` where `t` is the first parent's text — the point being that the same chunk produces the same ID across runs, unlike a random `uuid`.

**5.** Write `make_children(parent_docs: list, chunk_size: int = 400, chunk_overlap: int = 50) -> list` that uses `RecursiveCharacterTextSplitter(chunk_size=chunk_size, chunk_overlap=chunk_overlap).split_documents(...)`, stamps `doc.metadata["doc_id"] = stable_id(doc.page_content)` on each parent, and copies that same ID onto every child cut from it. Print `Created {len(child_docs)} Child Documents.`, print how many children share the `doc_id` of `parent_docs[0]`, and print `All children linked: {bool}` after checking that every child's `metadata["doc_id"]` appears in the set of parent IDs.

**6.** Build the summary chain yourself with `ChatPromptTemplate.from_template` and LCEL: `{"context": RunnablePassthrough()} | summary_prompt | llm | StrOutputParser()`, where the template is `Summarize the following core concepts concisely. Do not lose technical keywords.\n\nText: {context}`. Invoke it on each parent's `page_content`, wrap each result in a `Document` whose metadata carries the parent's `doc_id`, and print `Generated {len(summary_docs)} Summaries.` followed by one line per summary giving `{i} | {len(summary_text)} chars (parent was {parent_len} chars) | ratio {parent_len/summary_len:.1f}x | doc_id matches: {True or False}`.

**7.** Wire the two storage systems together: create `store = InMemoryByteStore()`, set `id_key = "doc_id"`, build `MultiVectorRetriever(vectorstore=vectorstore, byte_store=store, id_key=id_key, search_kwargs={"k": 2})`, run `retriever.docstore.mset([(doc.metadata[id_key], doc) for doc in parent_docs])`, then `retriever.vectorstore.add_documents(child_docs)` and `retriever.vectorstore.add_documents(summary_docs)`. Print `Multi-vector search index ready.`, then print how many parents you stored, how many children you uploaded, and how many summaries you uploaded, one per line.

**8.** Run a retrieval on the query `"Table 1 self-attention complexity"` and print what came back: for each document returned by `retriever.invoke(...)`, print `[Source {i + 1}] (Parent ID: {doc.metadata.get('doc_id', 'N/A')[:16]})` on one line, then `{len(doc.page_content)} chars` and the first 100 characters on the next. Confirm in a final line that every returned document is parent-sized rather than child-sized.

**9.** Prove the swap directly: query `vectorstore.similarity_search("Table 1 self-attention complexity", k=2)` and print `{len(doc.page_content)} chars | {first 80 characters}` for each raw hit, then query `retriever.invoke(...)` with the same string and print the same two fields for each returned document. Print `swap ratio: {parent_chars / raw_hit_chars:.1f}x` using the first raw hit and its parent, and one line stating whether any text the LLM will read is also text that was embedded.

**10.** Rebuild the parents with `make_parents(raw_text, chunk_size=2000, chunk_overlap=100)` instead of the lab's `10000`/`200`, print how many parents that produced and their mean character length, and print the mean character length of the `10000`/`200` parents side by side so the change in context granularity is visible before you re-index anything.

**11.** Re-index using the `2000`-character parents from the previous problem, then sweep the retriever's `search_kwargs`: call `retriever.invoke(...)` once with `search_kwargs={"k": 1}` and once with `search_kwargs={"k": 4}` on the lab's question `"What is the computational complexity per layer of a self-attention mechanism compared to a recurrent layer?"`. Print `k=1 -> {n} parents, {c} context chars` and `k=4 -> {n} parents, {c} context chars`, where `c` is the summed `len(doc.page_content)` of everything returned.

**12.** Break the document store on purpose: build a second `MultiVectorRetriever` whose `byte_store` is a fresh empty `InMemoryByteStore`, skip the `docstore.mset(...)` call entirely, and invoke it on the same question inside a `try`/`except`. Print `repr(e)` for whatever is raised, then fix it by running the `mset` call and print `Recovered: {len(retriever.invoke(...))} parents.`

**13.** Break the ID link on purpose: rebuild `child_docs` so that the children inherit the parent's original metadata but the line copying `doc_id` onto each child is removed, then try to `add_documents` those untagged children into a `MultiVectorRetriever` with `id_key="doc_id"`. Print the exception type and message you get, and print one line explaining what the retriever is unable to do without that metadata field.

**14.** Print a single line, and nothing else, that explains why `parent_docs` are passed to `retriever.docstore.mset(...)` but never to `retriever.vectorstore.add_documents(...)` — name what each of the two stores is for and what goes wrong if a 10,000-character parent is embedded and searched directly.

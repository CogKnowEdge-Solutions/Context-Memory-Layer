# Lab 15 Assignment: Agentic Hybrid RAG with Dynamic Routing — Coding Problems

Put what you learned in **Lab 15: Agentic Hybrid RAG with Dynamic Routing** into code — but go beyond the lab. The lab gave a self-correcting agent a choice between two Neo4j tools, routed by `router_node`, with a `fallback_node` that swaps tools before it ever rewrites the question, and it closed with a two-section answer. The problems below push past that: they read the database and the vector index back instead of trusting the ingestion log, run both Cypher branches on purpose, force the `No relevant information found in Neo4j.` safety net, flip the router's parsing logic to see what breaks, and decode the relationship types the LLM invented. Write each problem from scratch in a scratch Python file. Each problem says exactly what to print; print it.

**1.** Write the environment bootstrap: load `.env` with `python-dotenv`, then assert `OPENROUTER_API_KEY`, `NEO4J_URI`, `NEO4J_USER`, and `NEO4J_PASSWORD` are all set and non-empty. Print `✓ All environment variables loaded successfully`.

**2.** Configure `ChatOpenAI` with `openai_api_key=os.getenv("OPENROUTER_API_KEY")`, `openai_api_base="https://openrouter.ai/api/v1"`, `model_name="openai/gpt-oss-20b:free"`, and `temperature=0.0`, plus `HuggingFaceEmbeddings(model_name="all-MiniLM-L6-v2")`. Print `LLM and Embedding Models configured successfully!`, the client's `model_name`, and the dimension of the vector returned by `embeddings.embed_query("sequence transduction models")`.

**3.** Connect with `GraphDatabase.driver(NEO4J_URI, auth=(NEO4J_USERNAME, NEO4J_PASSWORD))`, then run `MATCH (n) RETURN count(n) AS total` and `MATCH ()-[r]->() RETURN count(r) AS total`. Print `Connected to Neo4j successfully!` followed by `Nodes: {total}` and `Relationships: {total}` read off the query results.

**4.** Read the ingested graph back out of the database rather than from the ingestion log: run `MATCH (n:Concept) RETURN n.name AS name` and print the count, then run `MATCH (a:Concept)-[r]->(b:Concept) RETURN type(r) AS rel_type, count(*) AS c` and print each relationship type with its count, highest count first.

**5.** Inspect the vector index you created: run `SHOW VECTOR INDEXES` and print the `name`, `entityType`, `labelsOrTypes`, and `properties` of each row, then print the `vector.dimensions` and `vector.similarity_function` options for `concept_embeddings`. Finally embed `"What is a transformer?"`, call `db.index.vector.queryNodes('concept_embeddings', 3, $vector)` and print each returned node name with its score to 4 decimals, which proves the index is actually populated.

**6.** Define the `AgentState` `TypedDict` with the keys `question`, `current_tool`, `retrieved_facts`, `grade`, `retry_count`, and `final_answer`, then hand-seed the initial state with `"question": "What models or mechanisms are sequence transduction models based on or connected to?"`, `"current_tool": ""`, `"retrieved_facts": []`, `"grade": ""`, `"retry_count": 0`, `"final_answer": ""`. Print the keys of `AgentState.__annotations__` in order, then print `current_tool` on its own line to show it is empty before the router runs.

**7.** Write `router_node(state: AgentState) -> AgentState` from scratch with the prompt describing `VECTOR` as best for general concepts and `GRAPH` as best for connections and multi-hop logic, normalizing with `state["current_tool"] = "GRAPH" if "GRAPH" in chosen_tool else "VECTOR"`. Run it on the seeded state and on a state whose question is `"What is a neural network?"`, printing `ROUTER DECISION: Using {state['current_tool']} Tool.` for each.

**8.** Break the router's parsing on purpose: write a second copy that swaps the condition to `"VECTOR" in chosen_tool`, run it on the same two questions from problem 7, and print the tool each one gets under both the original and the flipped version on one line per question — so the effect of the condition, not just the LLM's wording, is what gets compared.

**9.** Run both Cypher branches of `retrieve_node` directly against Neo4j. For the `GRAPH` branch, execute `CALL db.index.vector.queryNodes('concept_embeddings', 2, $vector)` yielding `node AS seed, score`, then `MATCH (seed)-[r]-(neighbor:Concept)` and return `seed.name + ' --[' + type(r) + ']-> ' + neighbor.name AS path` with `LIMIT 5`, printing the number of paths and the first path verbatim; for the `VECTOR` branch, return `n.name AS text` from a top-3 query and print each name on its own line.

**10.** Force the safety net deliberately: embed the gibberish string `"zzqx vwpl mrrk nothing here"` and run the `VECTOR` branch query with it, then run the `if not retrieved_data` guard from `retrieve_node` and print `state["retrieved_facts"]` verbatim so the `"No relevant information found in Neo4j."` fallback is confirmed by output rather than assumed.

**11.** Write `grade_node(state: AgentState) -> AgentState` from scratch with the same softened prompt that asks for ANY relevant hint and demands one word, normalizing with `state["grade"] = "YES" if "YES" in raw_grade else "NO"`. Run it on the placeholder fact from problem 10 and print `Grade: {state['grade']}`, then explain in one printed line whether a grading step that reads `"No relevant information found in Neo4j."` is really testing retrieval quality or just testing itself.

**12.** Write `fallback_node(state: AgentState) -> AgentState` from scratch with the two-stage rule: when `retry_count == 0` swap `current_tool` without touching the question, otherwise rewrite the question through the LLM, and always increment `retry_count`. Seed it once with `current_tool="GRAPH"`, `retry_count=0`, and a failing question and print the tool before, the tool after, and the new `retry_count`; seed it again with `current_tool="VECTOR"`, `retry_count=1` and print the rewritten question and the new `retry_count`, so both stages are exercised separately.

**13.** Write `route_after_grading(state: AgentState) -> str` from scratch, returning `"generate"` when `state["grade"] == "YES" or state["retry_count"] >= 2` and `"fallback"` otherwise, and print a decision table over `grade` values `"YES"` and `"NO"` crossed with `retry_count` values `0`, `1`, `2`, and `3` regardless of `current_tool`. After the table, print one line beginning `If the retry clause were removed:` naming the combination that would keep the graph cycling between `grade` and `fallback` forever.

**14.** Build and compile the graph with all five nodes — `router`, `retrieve`, `grade`, `fallback`, `generate` — wiring `fallback` back to `retrieve` rather than to `router`, print `Agentic Hybrid RAG Graph compiled successfully!`, and read back `sorted(agent.get_graph().nodes.keys())` plus every edge as `source -> target`. Then wrap the `agent.invoke(seeded_state)` call in `contextlib.redirect_stdout` so the nodes' own prints can be captured, and print the captured `ROUTER DECISION` line, `len(result["retrieved_facts"])`, `result["grade"]`, `result["retry_count"]`, the number of retrieved facts containing `"]->"` (the graph tool's path format), and the portion of `result["final_answer"]` that follows `--- EXPLAINABILITY ---`.

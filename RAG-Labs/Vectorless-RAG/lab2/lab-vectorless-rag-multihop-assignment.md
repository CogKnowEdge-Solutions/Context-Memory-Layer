# Lab 12 Assignment: Vectorless RAG: Multi-Hop Retrieval with Explainability Tracking — Coding Problems

Put what you learned in **Lab 12: Vectorless RAG: Multi-Hop Retrieval with Explainability Tracking** into code — but go beyond the lab. The lab built a three-stage pipeline where `PageIndexClient.submit_document` builds a tree of the Q4 2025 earnings release, `retrieve_from_pageindex` polls `submit_query` and `get_retrieval` until the status is `completed`, and turns the top five `retrieved_nodes` into hop dictionaries carrying `hop_number`, `section`, `node_id`, `pages`, and `text` — which `vectorless_rag` then joins into one context block for `global.amazon.nova-2-lite-v1:0`. The problems below rebuild that retrieval loop from scratch with a forced timeout and a forced `retrieval_id` miss, sweep `top_k` from 1 to 5 and report how much context each width buys, parse the `physical_index` strings like `<physical_index_6>` out of the API response by hand, seed an empty hop list to exercise the `"No relevant context found."` branch, tighten the prompt into a `[Hop X]` citation scheme that replaces the lab's `hop["section"] in final_answer` heuristic, and swap the Bedrock model plus `max_tokens` to see the truncation the default hides. Write each problem from scratch in a scratch Python file. Each problem says exactly what to print; print it.

**1.** Write the environment bootstrap: set `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_ENDPOINT_URL`, and `AWS_REGION = "ap-south-1"` as environment variables, prompt for the PageIndex key with `input()` and store it in `PAGEINDEX_API_KEY`, assert all five are non-empty, and instantiate `pi_client = PageIndexClient(api_key=PAGEINDEX_API_KEY)`. Print `Credentials configured.`, `PageIndex key loaded.`, and `Multi-hop retrieval environment ready.`

**2.** Write the download step from scratch: `requests.get` the URL `https://s21.q4cdn.com/736796105/files/doc_financials/2025/q4/Exhibit-99-1-Q4-2025-Earnings-Release.pdf`, call `response.raise_for_status()`, `os.makedirs("data", exist_ok=True)`, and derive the filename with `PDF_URL.split("/")[-1]` so it lands in `data/Exhibit-99-1-Q4-2025-Earnings-Release.pdf`. Print `Downloaded the document to 'data/Exhibit-99-1-Q4-2025-Earnings-Release.pdf'` and the byte count on the next line.

**3.** Write `wait_until_ready(client, doc_id, max_checks=60, delay=5) -> int` from scratch: loop at most `max_checks` times, break as soon as `client.is_retrieval_ready(doc_id)` is truthy, `time.sleep(delay)` between checks, and return the number of checks taken or raise `TimeoutError("PageIndex timeout")` if the loop runs out. Submit the PDF with `pi_client.submit_document(PDF_PATH)`, print `Document Submitted. Tracking ID: {doc_id}`, and print `Indexing Complete! The hierarchical tree is ready for multi-hop retrieval.` once the helper returns.

**4.** Write a recursive `count_nodes(node) -> int` returning `1` for a leaf and `1 + sum(count_nodes(c) for c in node.get("children", []))` otherwise, plus a recursive `count_parents(node) -> int` that counts only nodes with a non-empty `children` list. Fetch the tree with `pi_client.get_tree(doc_id, node_summary=True)["result"]`, print it with `utils.print_tree(tree)`, and then print `Total nodes: {n}`, `Root node_id: {root_id}`, and `Nodes with children: {p}`.

**5.** Force the timeout branch on purpose: call the helper from problem 3 with `max_checks=1` and `delay=0` against a `doc_id` that is not the real one, catch the `TimeoutError`, and print the exact line `PageIndex timeout`. Then print one line naming the single change that turns that hard failure into a retry instead.

**6.** Write `retrieve_from_pageindex(query, doc_id, top_k=5) -> list[dict]` from scratch: call `pi_client.submit_query(doc_id=doc_id, query=query)`, return `[]` immediately when `response.get("retrieval_id")` is falsy, then poll `pi_client.get_retrieval(retrieval_id)` until `status == "completed"` (returning `[]` on `status == "failed"`) while catching exceptions to survive rate limits and `time.sleep(3)` between attempts. For each of the first `top_k` nodes in `retrieved_nodes`, collect `relevant_contents` into text, pull page numbers out of each item's `physical_index` with `re.search(r"(\d+)", raw_page)`, and append a dict with keys `hop_number`, `section`, `node_id`, `pages`, and `text`. Print one line per hop in the form `Hop {hop_number}: {section} | node_id: {node_id} | pages: {pages}`.

**7.** Sweep the hop width and read the state back: call `retrieve_from_pageindex` three times for the same query with `top_k=1`, `top_k=3`, and `top_k=5`, and for each print `top_k={k} | hops: {len(hops)} | context chars: {total}`, where `total` is the summed length of every `hop["text"]`. Then print one line stating whether a single hop already contains enough text to answer, based on the character counts you just printed.

**8.** Write `parse_physical_index(raw) -> int | None` from scratch using `re.search(r"(\d+)", raw)` guarded by an `isinstance(raw, str)` check, and a small function that returns `sorted(set(pages))` for a hop list. Feed `parse_physical_index` the four values `None`, `"page 4"`, `"<physical_index_11>"`, and `""`, print the four results in that order, and then print `Distinct pages across all hops: {pages}` for the hops from problem 7.

**9.** Write `report_hops(hops) -> str` from scratch that returns the section with the longest `hop["text"]` and prints a line per hop in the form `Hop {n}: "{section}" | pages: {joined} | chars: {len(text)}`. After the loop print `Most text came from hop {hop_number}: {section}` and print the single longest `hop["text"]` value truncated to 200 characters.

**10.** Write `vectorless_rag(query, doc_id) -> tuple[str, list[dict], str]` from scratch: call `retrieve_from_pageindex`, return `"No relevant context found."`, `[]`, and `""` when there are no hops, join the hop texts with `"\n\n"` into `labeled_context`, and send the financial-analyst prompt — the one that says to answer in plain language and to consider seasonality rather than scaling one quarter by 4 — to `llm = ChatBedrockConverse(model="global.amazon.nova-2-lite-v1:0", temperature=0.0, max_tokens=300)`. Run it with the query `"How much did GAAP net income grow or shrink from Q1 2024 to Q1 2025? Separately, what was adjusted net income (not adjusted EBITDA) for both periods, and does it tell a different story?"`, print each `Hop {hop_number}: {section}` under `--- SECTIONS SEARCHED (RETRIEVAL TRACE) ---`, then print `--- FINAL ANSWER ---` and the answer.

**11.** Seed the empty state by hand to exercise the branch the real query never hits: temporarily replace `retrieve_from_pageindex` with a stub that returns `[]`, call `vectorless_rag` again, and print `Answer: No relevant context found.` followed by `Hops returned: 0`. Then restore the real function and print `Restored real retrieval.`

**12.** Reproduce the lab's explainability heuristic from scratch: compute `was_used = hop["section"] in final_answer` for every hop, derive `status` as `"LIKELY USED in answer"` when true and `"retrieved context"` otherwise, and print one block per hop with `Hop {n}: "{section}"`, `node_id: {node_id} | page(s): {pages} | {status}`, and a count of how many hops came back as `"LIKELY USED in answer"`. Then print one line explaining in a single sentence why a section the answer paraphrases without naming can still be marked `retrieved context`.

**13.** Replace the heuristic with strict citation tracking: rewrite the answer prompt inside `vectorless_rag` so the LLM must tag every fact inline as `[Hop 1]`, `[Hop 2]`, and so on, re-run the same earnings query, and print `Distinct [Hop X] tags found: {n}` alongside `Hops retrieved: {m}` and a boolean `All hops cited: {True or False}`. Compare that boolean against the count you printed in problem 12 for the same query.

**14.** Swap the model and the token budget: rebuild `llm` as `ChatBedrockConverse(model="global.anthropic.claude-haiku-4-5-20251001-v1:0", temperature=0.0, max_tokens=800)`, re-run `vectorless_rag` for the same query, and print `Characters in answer: {len(final_answer)}`. Then print one line stating whether the 800-token budget changed the answer's length relative to the 300-token `global.amazon.nova-2-lite-v1:0` run, naming which of the two finished mid-sentence if either did.

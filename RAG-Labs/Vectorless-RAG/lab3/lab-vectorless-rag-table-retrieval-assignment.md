# Lab 12 Assignment: Vectorless RAG: Structured Table Retrieval with Explainability Tracking — Coding Problems

Put what you learned in **Lab 12: Vectorless RAG: Structured Table Retrieval with Explainability Tracking** into code — but go beyond the lab. The lab kept whole financial tables intact with `PageIndexClient`, pulled the top matching table nodes back with `retrieve_from_pageindex`, tagged every figure with `[Table 1]`-style citations, and proved which tables were used by checking for those tags in the final answer. The problems below go past that: they read the indexed tree back instead of eyeballing the printed outline, vary `top_k`, exercise the `failed` and missing-`retrieval_id` branches with a bad `doc_id`, parse `physical_index` strings on their own, and strip the citation instruction to show what the used-or-not check is actually measuring. Write each problem from scratch in a scratch Python file. Each problem says exactly what to print; print it.

**1.** Write the environment bootstrap: load `.env` with `python-dotenv`, then assert `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_ENDPOINT_URL` set to `https://api.enterprisesi.co/api/v1/aws-genai/bedrock-runtime`, `AWS_REGION` set to `ap-south-1`, and `PAGEINDEX_API_KEY` are all present. Print `✓ All environment variables loaded successfully`.

**2.** Download `https://s21.q4cdn.com/736796105/files/doc_financials/2025/q4/Exhibit-99-1-Q4-2025-Earnings-Release.pdf` with `requests` and write it to `data/Exhibit-99-1-Q4-2025-Earnings-Release.pdf`. Print `Downloaded the financial document to '{PDF_PATH}'` followed by the file size in KB from `os.path.getsize`.

**3.** Build `pi_client = PageIndexClient(api_key=PAGEINDEX_API_KEY)`, call `pi_client.submit_document(PDF_PATH)`, and store `doc_info["doc_id"]`. Print `Document Submitted. Tracking ID: {doc_id}`.

**4.** Poll `pi_client.is_retrieval_ready(doc_id)` in a `while` loop with `time.sleep(5)` between checks, counting how many polls it took. Print the poll count and then `Indexing Complete! The document's structure is fully preserved.`

**5.** Fetch the tree with `pi_client.get_tree(doc_id, node_summary=True)["result"]`, print it with `pageindex.utils.print_tree(tree)`, and then walk the returned structure yourself: collect every table node's title and `node_id` and print `Tables found: {count}` followed by each title with its `node_id` on one line, so the tables are read back programmatically rather than only seen in the printed outline.

**6.** Prove the keep-whole claim instead of asserting it: take the longest table node's text from problem 5, print its character count, then print how many pieces `RecursiveCharacterTextSplitter(chunk_size=300, chunk_overlap=50).split_text(...)` would cut that same text into. After those two numbers, print one line beginning `A word-count splitter would separate:` naming what it risks cutting away from the rows.

**7.** Write `retrieve_from_pageindex(query, doc_id, top_k=2)` from scratch: call `pi_client.submit_query(doc_id=doc_id, query=query)`, return `[]` when `retrieval_id` is missing, poll `pi_client.get_retrieval(retrieval_id)` with `time.sleep(1)` until `status` is `completed`, return `[]` when it is `failed`, and otherwise build one dict per node with the keys `table_number`, `section`, `node_id`, `pages`, and `text`. Run it on `"What was the total revenue for the three months ended March 31, 2025?"` and print the number of tables returned plus each one's `section` and `node_id`.

**8.** Break the retrieval call on purpose: invoke your function from problem 7 with a bogus `doc_id` of `"00000000-0000-0000-0000-000000000000"`, catch whatever error is raised, and print one line reading `Returned {len(tables)} tables` for the empty list it produces — showing whether a bad document id surfaces as an empty result or as an exception you had to handle.

**9.** Write a standalone parser for the page index: take the raw strings `"<physical_index_6>"`, `"<physical_index_12>"`, and `""`, run `re.search(r"(\d+)", raw)` on each when it is a `str`, and print the extracted page number for each on its own line with `(none)` where no digits are found. Then run the same logic over the `physical_index` values of the tables from problem 7 and print the deduplicated page list for each.

**10.** Re-run `retrieve_from_pageindex` with `top_k=4` on the same query and print, for each table returned, `table_number`, `section`, `node_id`, the joined `pages`, and the character count of `text` — then print `Tables returned: {count}` so the effect of raising `top_k` on the retrieved set is visible.

**11.** Write `vectorless_rag(query, doc_id)` from scratch: call your retrieval function, return `"No relevant context found."` with an empty table list and empty context when nothing comes back, otherwise build `labeled_context` as `"[Table {t['table_number']} - {t['section']}]\n{t['text']}"` joined by blank lines, and prompt `ChatBedrockConverse(model="global.amazon.nova-2-lite-v1:0", temperature=0.1)` with the `CRITICAL INSTRUCTIONS` that every number must be tagged with its table and that missing data must be reported as `Not found in document.`. Print the answer, then print only the header line of each block in `labeled_context`.

**12.** Write the explainability pass from scratch: for each table compute `was_used = f"[Table {t['table_number']}]" in final_answer` and print `Table {n}: "{section}"`, its `node_id`, its pages joined by commas, and either `USED in answer` or `retrieved but NOT used`, followed by the `Why:` explanation from a second LLM call built from that table's actual rows. Close by printing `Used: {used_count} of {total}`.

**13.** Ask a question that should need two tables — `"What was total revenue for the three months ended March 31, 2025, and how many homes were closed in the same period?"` — run it through your `vectorless_rag`, and print the number of distinct `[Table n]` tags found with `re.findall(r"\[Table \d+\]", final_answer)` alongside the titles of the tables retrieved, so you can see whether one table really answered it or two were needed.

**14.** Break the explainability check on purpose: build a copy of your prompt with the `CRITICAL INSTRUCTIONS` block deleted, run the same query, and print `was_used` for every retrieved table under both prompt versions. After that, print one line beginning `This check measures:` explaining that a table the model read but failed to tag is reported as unused, and why the tag has to be enforced rather than inferred.

# Lab 10 Assignment: Hybrid RAG: Vector Search + Graph Traversal on Neo4j — Coding Problems

Put what you learned in **Lab 10: Hybrid RAG: Vector Search + Graph Traversal on Neo4j** into code — but go beyond the lab. The lab extracts entities and relationships from the Attention Is All You Need PDF into `:Concept` nodes, stores a 384-dimension `all-MiniLM-L6-v2` vector on each node, indexes them as `concept_embeddings`, and answers a question with one Cypher call that combines `db.index.vector.queryNodes` seed selection with `(seed)-[r]-(neighbor:Concept)` expansion. The problems below add hand-built orphan relationship entries, read the node, relationship, and vector counts back out of Neo4j instead of assuming them, break the vector index with a mismatched `vector.dimensions`, sweep `top_k`, exercise the empty-facts guard, and print the graph the traversal actually used. Write each problem from scratch in a scratch Python file. Each problem says exactly what to print; print it.

**1.** Write the environment bootstrap: call `load_dotenv()`, then assert that `os.environ["NEO4J_URI"]`, `os.environ["NEO4J_USER"]`, `os.environ["NEO4J_PASSWORD"]`, and `os.environ["OPENROUTER_API_KEY"]` are all non-empty, and print `✓ All environment variables loaded successfully`.

**2.** Open the connection and both clients from scratch: build `driver = GraphDatabase.driver(os.getenv("NEO4J_URI"), auth=(os.getenv("NEO4J_USER"), os.getenv("NEO4J_PASSWORD")))`, call `driver.verify_connectivity()` and print `Success: Connected to Neo4j Database!`. Then build `llm = ChatOpenAI(openai_api_key=os.getenv("OPENROUTER_API_KEY"), openai_api_base="https://openrouter.ai/api/v1", model_name="nvidia/nemotron-3-ultra-550b-a55b:free", temperature=0.0)` and `embeddings = HuggingFaceEmbeddings(model_name="all-MiniLM-L6-v2")`, and print `Embedding dimensions: {len(embeddings.embed_query("attention"))}` so the 384 in the index config is verified before any Cypher runs.

**3.** Rebuild the document step: `os.makedirs("data", exist_ok=True)`, download `PDF_URL = "https://arxiv.org/pdf/1706.03762.pdf"` with `requests.get`, call `response.raise_for_status()`, write it to `data/downloaded_paper.pdf`, then loop `PdfReader` pages into `document_text` and break once the string reaches 1500 characters. Print `PDF downloaded successfully to data/downloaded_paper.pdf!` and `Extracted {len(document_text)} characters of text.`.

**4.** Rebuild the extraction call: send the data-extraction prompt asking for `nodes` and `relationships` as two separate JSON lists, invoke `llm.invoke(prompt)`, strip a leading markdown code fence and its trailing `json` language tag when present, and `json.loads` the reply into `graph_data`. Print `Extracted {len(graph_data.get('nodes', []))} nodes and {len(graph_data.get('relationships', []))} relationships!`, then collect the distinct `type` values from `relationships` into a `set` and print them one per line as `RELATION_TYPE: {rel_type}`.

**5.** Write the nodes from scratch with `UNWIND $nodes AS node MERGE (c:Concept {name: node.name})` passed through `session.run(node_query, nodes=graph_data.get("nodes", []))`, print `Nodes saved to Neo4j!`, then read the count back with `MATCH (c:Concept) RETURN count(c) AS total` and print `Concept nodes in DB: {total}`, followed by `MATCH (c:Concept) RETURN c.name AS name ORDER BY name` printed one name per line so you can confirm `MERGE` did not duplicate anything across two runs.

**6.** Write the relationships from scratch with the `apoc.create.relationship` query that ends in `replace(toUpper(rel.type), ' ', '_')` inside a `if graph_data.get("relationships"):` guard, print `Relationships saved to Neo4j!`, then read them back with `MATCH ()-[r]->() RETURN type(r) AS relationship_type, count(*) AS occurrences ORDER BY relationship_type` and print `Total relationships: {total}` plus one `  {relationship_type}: {occurrences}` line per row, so the uppercased-and-underscored types such as `BASED_ON` are visible rather than assumed.

**7.** Break the relationship write on purpose: append one hand-built entry `{"source": "Encoder", "target": "Nonexistent Node", "type": "PART_OF"}` to the relationship list and re-run the same `apoc.create.relationship` query. Print `Requested entries: {requested}` and `MATCH resolved both ends for: {matched}` by first running `MATCH (s:Concept {name: $source}) MATCH (t:Concept {name: $target}) RETURN count(*) AS n` for that entry, then print `Relationships created from the orphan entry: 0` — followed by one printed line explaining in a single sentence why a relationship whose endpoints never matched silently disappears instead of raising.

**8.** Create the vector index from scratch with `CREATE VECTOR INDEX concept_embeddings IF NOT EXISTS FOR (c:Concept) ON (c.embedding) OPTIONS {indexConfig: {'vector.dimensions': 384, 'vector.similarity_function': 'cosine'}}`, then read it back with `SHOW INDEXES YIELD name, type, state, entityType WHERE name = 'concept_embeddings'` and print `Index name: {name}`, `Index type: {type}`, `Index state: {state}`, and `Indexed property: embedding` — confirming the label and property the lab's `FOR (c:Concept) ON (c.embedding)` actually bound to.

**9.** Backfill the node vectors with the two-query pattern: first `MATCH (c:Concept) WHERE c.embedding IS NULL RETURN elementId(c) as node_id, c.name AS text`, then for each record embed the name and `SET c.embedding = $vector` via `MATCH (c) WHERE elementId(c) = $node_id`. Print `All nodes already have embeddings.` when the record list is empty, otherwise print `Generating vectors for {len(records)} nodes...` and `Success: All graph concepts vectorized!`. Run the whole block twice and print `Second pass produced: {second_pass}` records so the `WHERE c.embedding IS NULL` filter is visibly doing its job.

**10.** Break the index on purpose: drop `concept_embeddings`, recreate it with `'vector.dimensions': 768` while `all-MiniLM-L6-v2` still emits 384 numbers, and call `db.index.vector.queryNodes('concept_embeddings', 3, $question_vector)`. Catch the Neo4j error, print `Caught: {type(e).__name__}` and the first 200 characters of its message, then recreate the index with 384, re-run the same query successfully, and print `Recreated with vector.dimensions: 384 — query now returns {len(result)} rows.` so the failure and the fix both appear in the output.

**11.** Reimplement `execute_hybrid_retrieval(driver, question, top_k=3)` with `embeddings.embed_query(question)` and the single Cypher call `CALL db.index.vector.queryNodes('concept_embeddings', $top_k, $question_vector) YIELD node AS seed, score MATCH (seed)-[r]-(neighbor:Concept) RETURN seed.name AS Seed_Node, score AS Semantic_Score, type(r) AS Relationship, neighbor.name AS Connected_Node`. Print `User Question: 'What models or mechanisms are discussed in the document?'`, the `RETRIEVED HYBRID PATHS:` header, a 60-character rule, and then one line per record formatted exactly as `(Similarity: {record['Semantic_Score']:.2f}) {record['Seed_Node']} --[{record['Relationship']}]--> {record['Connected_Node']}`. **12.** Sweep the seed width by calling your `execute_hybrid_retrieval` on the same question with `top_k=1`, `top_k=3`, and `top_k=8`.
